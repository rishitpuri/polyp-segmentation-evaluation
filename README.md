# What Polyp Segmentation Benchmarks Cannot Measure

[![DOI](https://zenodo.org/badge/1360891906.svg)](https://doi.org/10.5281/zenodo.22841360)

Code, splits and per-image results for a measurement study of polyp
segmentation evaluation. Five architectures are trained under one recipe with
five-fold cross-validation on Kvasir-SEG and evaluated zero-shot on four
external datasets; the run-to-run noise floor of the protocol is measured
directly by repeating identical configurations.

**Headline results**

1. On lesions occupying less than 1% of the image, per-lesion detection falls
   to **0.44–0.59** (from 0.86–0.89 on larger lesions): models miss roughly
   half of clinically small polyps. Kvasir-SEG contains **6 such images out of
   1000**, so the standard benchmark cannot see this failure. The four
   external sets contain 123.
2. Repeating an identical configuration (same seed, fold and data) gives a
   test-Dice spread up to 0.017, with **σ_run = 0.0053**. **4 of 10** pairwise
   in-domain architecture comparisons fall below this floor. The cause is
   **checkpoint selection on a flat validation curve**, not seeding or CUDA
   non-determinism: identical runs select epochs 11.3 apart on average
   (r = 0.49 with test-Dice divergence), while validation-Dice differences are
   uninformative about test differences (r = 0.004).
3. Architecture spread is **3.9σ** in domain but **21.6σ** on ETIS-Larib, so
   cross-dataset evaluation resolves architectures that in-domain evaluation
   cannot.
4. A subgroup finding from our own single-split analysis (U-Net++ appearing
   immune to the flat-lesion penalty) **failed to replicate** under
   cross-validation.

## Data

Not redistributed. Obtain from the original providers:

| Dataset | Images | Role | Source |
|---|---:|---|---|
| Kvasir-SEG | 1000 | train + in-domain test | https://datasets.simula.no/kvasir-seg/ |
| Kvasir-Sessile | 196 | sessile stratum label | https://datasets.simula.no/kvasir-seg/ |
| CVC-ClinicDB | 612 | external test | https://polyp.grand-challenge.org/CVCClinicDB/ |
| CVC-ColonDB | 380 | external test | PraNet benchmark pack |
| ETIS-LaribPolypDB | 196 | external test | PraNet benchmark pack |
| CVC-300 | 60 | external test | PraNet benchmark pack |

The last three come most easily from the test pack distributed with PraNet
(https://github.com/DengPingFan/PraNet). **Two folders in that pack must not
be used here:** its `Kvasir` subset overlaps our training data, and its
62-image `CVC-ClinicDB` subset is superseded by the full 612 images.

Expected layout:

```
Kvasir-SEG/{images,masks}/            # 1000 + 1000
sessile-main-Kvasir-SEG/images/       # 196 (names index into Kvasir-SEG)
data/external/<name>/{images,masks}/  # one directory per external dataset
```

`run_cv.sh` auto-detects anything under `data/external/`.

## Reproducing

Local (analysis, figures, manuscripts — no GPU):

```bash
python3 -m venv .venv
.venv/bin/pip install torch torchvision segmentation-models-pytorch \
    albumentations opencv-python-headless scipy pandas scikit-learn \
    matplotlib tqdm pymupdf
```

On a GPU machine, do **not** reinstall torch if the image already ships a
CUDA build; install only the rest:

```bash
pip install -r polypseg/requirements-pod.txt
```

Then from the project root:

```bash
# 1. metadata and strata
python polypseg/scripts/01_data_audit.py
python polypseg/scripts/10_external_metadata.py

# 2. splits
python polypseg/scripts/02_make_splits.py      # single split
python polypseg/scripts/04_make_cv_folds.py    # 5 folds

# 3. experiments (GPU; ~7 h total on one RTX 4090)
bash polypseg/run_all.sh       # single-split protocol
bash polypseg/run_cv.sh        # 5-fold CV, 5 models
bash polypseg/run_repeat.sh    # variance, conditions A/B
bash polypseg/run_repeat2.sh   # variance, conditions C/D

# 4. analysis, figures, tables
python polypseg/scripts/11_analyze_final.py
python polypseg/scripts/12_figures_final.py
python polypseg/scripts/13_make_tables_final.py

# 5. qualitative panel (GPU; needs fold-0 models in polypseg/runs_qual)
python polypseg/scripts/14_qualitative_final.py

# 6. manuscript
cd polypseg/paper_journal && latexmk -pdf main.tex
```

All run scripts are resumable: any run with an existing `summary.json` is
skipped, so an interrupted job restarts without losing work.

Together these produce the **88 training runs** the manuscript reports:
9 single-split (3 models x 3 seeds), 25 cross-validation (5 models x 5 folds),
19 + 30 repeat-variance runs across four determinism conditions, and 5 fold-0
models for the qualitative panel.

## Protocol

- **Architectures.** U-Net (ResNet-34), U-Net++ (ResNet-34), SegFormer-B0,
  SegFormer-B2, U-Net + PVTv2-B2 — four backbone families, 3.7M–28.1M
  parameters, identical training recipe so architecture is the only variable.
- **Training.** 352×352, AdamW (lr 1e-4, wd 1e-4), cosine schedule, batch 16,
  ≤60 epochs, early stopping (patience 15) on validation Dice, Dice+BCE,
  bfloat16 autocast.
- **Cross-validation.** 5 folds stratified on size tertile × sessile;
  700 train / 100 val / 200 test per fold. Every image tested exactly once.
- **Metrics.** Predictions are resized to native resolution before scoring.
  Dice, IoU, precision, recall; Boundary-F1 with tolerance at 0.5% of the
  image diagonal (a fixed pixel tolerance is not comparable across images
  differing five-fold in size); HD95 absolute and as % of diagonal; and
  per-lesion detection rate plus false positives, because region overlap
  scores a multi-lesion image as one region.
- **Statistics.** Paired Wilcoxon with Holm correction for architectures;
  two-sided permutation tests on the difference of means with percentile
  bootstrap intervals for stratum contrasts, so interval and p-value describe
  the same estimand.

## Recommendations that follow from the results

1. Report a measured noise floor and do not interpret differences below it.
   A handful of repeated runs is enough to estimate it.
2. Do not rely on seeds or `torch.use_deterministic_algorithms` for
   reproducible comparisons — neither removed the variance here. The
   procedural fixes are weight averaging over final epochs, smoothed
   selection criteria, larger validation sets, or averaging repeated runs.
3. Include datasets containing genuinely small lesions; Kvasir-SEG alone
   cannot measure the dominant clinical failure mode.
4. Report per-lesion detection alongside overlap metrics when multifocal
   images occur.

## Limitations

- Kvasir-SEG has no patient identifiers, so splits are image-level and frames
  from one procedure may co-occur across folds. This affects both protocols
  compared and does not bear on the replication argument.
- Size strata use relative lesion area; physical size is not recorded.
- The variance study uses three runs per configuration on one fold and one
  GPU model. Re-running the full cross-validation on different hardware
  shifted mean Dice by up to 0.005, so the cross-hardware floor is no smaller.
- Specialised polyp networks (PraNet, Polyp-PVT) were not retrained;
  reproducing them under a different recipe risks understating them, so their
  backbone families are spanned instead under one controlled recipe.
- Results are on curated still frames and do not establish clinical utility.
